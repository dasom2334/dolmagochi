# 거실 씬 실험 기록 (2026-07-19 ~ 07-20)

돌마고치 방/거실 씬의 비주얼 아키텍처를 확정하는 작업.
이 문서만 읽으면 맥락 없이 이어서 작업할 수 있도록 모든 결정·레슨을 기록한다.

## 0. 전제 — 매번 헷갈렸던 것들 (먼저 읽을 것)

이 절은 **같은 오해를 반복해서 사용자가 정정해준 내용**이다. 추측으로 뒤집지 말 것.

### 0.1 PixelLab PNG 에셋 파이프라인은 **전량 폐기**
- 생성 파이프라인이 힘들어서 포기했다. **모든 아트는 코드로 그린다.**
- 따라서 "PNG 에셋 제작 기준을 만든다"는 옛 목표는 **더 이상 유효하지 않다.**
  그 전제로 쓰인 문장이 아래에 남아 있으면 낡은 것이다.
- 잔해: `src/components/scene/LivingRoomArt.tsx`, `public/assets/`,
  `design/generated/`, `design/tools/`. **일단 남겨두되 되살리지 않는다.**
  (LivingRoomArt.tsx는 SceneView가 import 중이라 지우면 빌드가 깨져서 남아 있는 것뿐)

### 0.2 기존 게임 씬 컴포넌트는 **신경 쓰지 않는다**
- `src/components/scene/`의 Floor·WindowSprite·RockSprite·TreeSprite 등은
  SVG도 아니고 픽셀 격자도 없다. `<div>` + CSS(퍼센트와 생px 혼용)다.
- 전부 대체될 예정이므로 **제약 조건이 아니다.** 좌표를 맞출 필요 없다.

### 0.3 논리 해상도는 **96×72**
- 레퍼런스가 그 격자로 측정됐고(셀 15.08px), v2 좌표가 전부 그 기준이다.
- `LivingRoomArt.tsx`의 160×120은 폐기된 PNG 크기라 **무시한다.**
- 남은 문제 하나: 96×72는 4:3, 게임 씬 박스는 480×270(16:9). 합칠 때 정한다.

### 0.4 살아 있는 산출물은 **`v3.html` 하나**
- v3 = 런타임 생성 + canvas. 씬 로직이 전부 `scene/` 에 있고 **빌드 단계가 없다.**
- `old/`는 전부 폐기(v1 `index.html`, 실험 `layers.html`, **구운 SVG였던 `v2.html`** 포함). 되살리지 말 것.
- 최종은 **canvas 로 React 프로젝트에 통합**. `scene/` 을 그대로 옮기면 된다.

### 0.5 측정은 **1회성이 아니다**
- 방 2개 + 외부 2개 이상 + 이벤트 씬 몇 장이 더 온다.
- 그래서 Python 추출 도구는 아카이브가 아니라 **정식 도구**다.
  단 지금은 거실 좌표가 하드코딩돼 있어 씬별 재사용이 안 된다(§5).

### 0.6 브랜치
- 아트 작업은 **`feat/livingroom-art`**. `feat/content-track`은 콘텐츠 전용 — 건드리지 말 것.
- design/은 .gitignore 대상 → 커밋 시 `git add -f design/livingroom/`.

## 2. 파이프라인 (재생성 순서)

새 씬을 측정할 때만 돌린다. **평소 작업(색·모양 수정)에는 필요 없다** — `scene/*.js` 를 고치고 새로고침하면 끝.

```
refgrid.npy            # 레퍼런스 96×72 다운샘플 (셀별 median). 캐시됨
  ↓ delight.py         # 휘도 플랫필드(광 웅덩이·글로우·비네트 제거) + 웜캐스트 60% 중화
refgrid_v2.npy
  ↓ prep_v3.py         # 텍스처 전사 (현재 러그만 사용. 질감만, 크로마 전사 금지!)
refgrid_v3.npy
  ↓ gen.py refgrid_v3.npy _v2      # 측정만: 셀 마스크 → 리전 k-means → 인페인팅 → rect
art_svg_v2.txt + palette_css_v2.txt
  ↓ export_room.py                 # 추출 그룹만 뽑고 punch() 대비 보정 적용
scene/room-data.js               # ← 여기서 Python 끝. 나머지는 전부 JS 런타임
```

추출 vs 절차 생성 분담 (2026-07-20 확정):
- **추출**: 벽·창틀·벽난로·책장(정적 구조), 불꽃·촛불·해(발광체 원색)
- **절차/수작화**: 창밖 배경 전체(synth: 10단 하늘 그라디언트 + 겹산 3중 실루엣 + 태양 후광, 풀캔버스),
  나무 2시안(v1 클럼프 침엽 / v2 타원 로브 활엽 — 둘 다 줄기 지면까지),
  마룻바닥(원근 판자), 러그(외곽 단+밝은 테두리 줄+무늬 필드), 돌 2종(ball 절차, 창턱 축소판+러그 원본 크기)
- 팔레트 소유권: 하늘 `--k0..k9` / 산 `--h0..h3` / 나무 `--t0..t4` 는 **scene/palette.js** 가 소유(시간·계절별 오버라이드).
  나머지 방·소품 팔레트는 gen.py k-means → export_room.py punch() 대비 보정 → room-data.js.

스크립트는 실행 디렉토리에서 중간 산출물을 찾는다 — **tools/ 안에서 실행할 것.**
(v1 파이프라인은 `old/`로 내렸다. §0.4)

## 3. 검증 완료 (확정 사항)

### 3.1 에셋 아키텍처 — 3계층 합성
```
기본 방(중립) + 소품(중립)
→ 시간 색감 오버레이 (낮/노을/밤, multiply)
→ 날씨 색감 오버레이 (맑음=없음/흐림/비/눈, multiply)
→ 광원 (개별 셰이프 5종, 각자 Light Mask)
→ emission (발광체, 최상단)
```
- 오버레이 2장 중첩 = 계산된 최종 오버레이 1장과 수학적으로 등가 (multiply 결합법칙). 제작은 분리 관리, 렌더링은 중첩으로 OK.
- 48조합(3×4×4)이 12장 배경이 아니라 레이어 합으로 표현됨을 실증.

### 3.2 소품 4레이어 (에셋 제작 단위)
| 레이어 | 블렌드 | 대상 | 내용 |
|---|---|---|---|
| base | normal | 전부 | 중립 색·입체감·AO만 |
| shadow | multiply 12~40% | 전부 | 접지 그림자·틈새 (시간 불변) |
| emission | 최상단 배치 | 발광체만 | 불꽃·촛불 화염·스탠드 전구 — 밤에도 안 어두워짐 |
| lightmask | 화면 비표시 | 렌더러 지원 시 | 오클루더(빛 차단 실루엣) |

- **highlight 레이어는 비채택** — 시간별 광원 방향이 바뀌므로 구우면 어색해짐.
- SVG는 네이티브 `<mask>`, canvas는 오프스크린 + `destination-out`으로 lightmask 구현 가능.
  (PNG 에셋 방식은 폐기 — §0.1)

### 3.3 물리 광원 규칙
- **창문 빛 = 앞(아래)으로 퍼지는 사다리꼴** (pool_trap): 창턱에서는 창 폭 그대로, 바닥에서 행마다 spread(원근 확산)+skew(저고도 좌측 흐름). 멀리언 그림자도 같은 변환으로 확대·이동. **수평면(창턱 상단 y35-36·바닥 y49+)에만** 투영, 창 밑 벽은 그림자.
- **셰이프는 낮·노을·밤 하나로 통일**(spread .035 / skew .55, 마스크도 m-win 하나). 시간에 따라 바뀌는 것은 **색(--wl/--ml)과 세기(--wl-a/--ml-a)뿐**. 고도별로 빔 길이를 다르게 하면 물리적으로는 맞지만 전환이 튀어 보여 채택하지 않음(2026-07-20 결정).
- **벽난로 = 점광원**: 역제곱 감쇠 3단 링(바닥+벽). 촛불=소반경, 스탠드=전기등(플리커 없음).
- **광원 = 셰이프(고정) × 색·세기 테이블**: `--wl/--wl-a` 등 팔레트 슬롯. 캐스케이드: 시간이 기본값 → 날씨가 나중에 오버라이드 → 계절은 컴파운드 예외(겨울 낮=차가운 흰 빛).
- **그림자 = Light Mask + 오클루더**: 광원마다 mask(창문=m-win, 벽난로=m-fire), 소품별 오클루더(.occ-orb/.occ-orb2/.occ-plant/.occ-props)가 소품 토글과 연동(끄면 그림자도 사라지고 빛 통과). 마스크 그레이 레벨 = 반그림자.
- 벽난로 불빛의 그림자(상자)는 광원 그룹 소속 → 불빛 끄면 그림자도 꺼짐(물리적으로 올바름).

### 3.4 z-순서 (뒤 → 앞)
```
[1] 방 구조   벽 → 바닥 → 창틀·창턱 → 벽난로 → 책장  (+각자 p-shadow)
[2] 창밖      하늘 → 해 → 달 → 별 → 구름 → 나무 → 비·눈·계절 파티클 → 유리 효과
[3] 소품      책장 책 → 촛대 → 창턱 화분 → 창턱 돌 → 러그 → 러그 돌 → 스탠드 → 바닥 소품
              (선반 안 → 맨틀 → 창턱 → 바닥 깔개 → 바닥 스탠딩 순. 러그는 깔개라 바닥 소품보다 뒤)
              돌 위치는 state.orb('sill' 기본/'rug') — 각 돌에 자기 오클루더(occ-orb/occ-orb2) 연동
[3.5] 창틀 눈쌓임 (날씨 틴트 받도록 오버레이 앞)
[4] 색감 오버레이  시간 → 날씨
[5] 광원(mask)    창문 햇빛 → 달빛 → 벽난로 → 촛불 → 스탠드
[6] emission      불꽃 → 촛불 화염 → 스탠드 전구
```

### 3.5 축별 책임
- **시간**: 하늘 팔레트(k0~k9) + 해↔달·별 + 광원 색/세기 + 산 실루엣(노을·밤) + 나무 톤 오버라이드
- **계절**: 창밖 나무(t0~t2 잎, 겨울=잎 숨김+앙상한 가지) + 산(h0~h3) + 계절 파티클(봄 꽃잎/가을 낙엽/여름밤 반딧불) + 성에(겨울)
- **날씨**: 구름(흐림·비·눈 공용) + 파티클(비/눈) + 광원 감쇠 + 해·달·별 숨김 + 창문 효과(빗방울 유리/창틀 눈쌓임)
- 컴파운드 예외: 밤+겨울 언덕(달빛 눈), 노을+겨울 언덕(장밋빛 눈), 낮+겨울 창문 빛(찬 흰색),
  밤+봄/가을 나무(가라앉은 톤). 노을 언덕(자주·핑크)과 밤 나무는 시간 오버라이드로 추가됨(2026-07-20)

### 3.6 풀캔버스 배경 (synth 절차 재작화, 2026-07-20 2차)
창은 벽의 구멍일 뿐 — 풍경은 캔버스 전체(96×72)에 존재(클립 없음). gen.py `synth(y,x)`:
- **하늘 = 10단 그라디언트**(k0 천정 → k9 지평선). 레퍼런스 수직 단면(x63) 실측색 그대로.
  **디더 없이 solid 행 밴드** — 스톱이 촘촘하면(≈2행/스톱) 계단이 안 보이고, 디더를 넣으면 오히려 격자 무늬로 읽힌다. 매핑 `round((y-4)/2.1)`.
- **산 = 겹산 3중 실루엣**(RIDGE_FAR/MID/NEAR 제어점 선형보간). 각 산맥은 **단색 + 자기 능선 1px 밝은 림**. 경계에 디더를 섞으면 얼룩이 되므로 섞지 않는다. h3(원산)→h0(근산·지면).
- 태양 후광: 방사형이라 solid 밴드면 동심원 링이 보임 → **여기만 해시 지터**로 경계를 흩뜨림. 밤엔 같은 자리가 달무리.
- 얇은 층운 4줄(y8/11/14/17): 한 스톱 밝게, 양끝만 지터 페이드.
전부 `var(--k·--h)` 참조라 시간·계절 테마 연동.

### 3.7 하늘은 알베도가 아니다
하늘·해·불꽃은 **광원**이므로 디라이팅·양자화 대상에서 제외하고 레퍼런스 원본색을 그대로 쓴다.
k-means로 뽑은 하늘 팔레트는 그라디언트가 뭉개져 못 쓴다 → 팔레트 소유권은 scene/palette.js.
같은 이유로 시간 오버레이의 `glass()` 틴트도 약하게(노을 .16 / 밤 .09) — 하늘 팔레트가 이미 그 시간의 색이라 이중 착색되면 어두워진다. 대신 나무는 시간별 팔레트 오버라이드로 직접 물들인다.

## 4. 배운 것 (레슨 로그)

1. **레퍼런스 재현은 감이 아니라 추출**: 셀 크기는 행/열 차분 자기상관으로 측정(15.08px), 색은 리전별 k-means, 그림은 다운샘플 그리드를 run-merge된 rect로 방출(~1,800개).
2. **전역 k-means는 소수 색을 흡수한다** — 돌 회색(~120셀)이 핑크 클러스터에 먹혔음. 리전별 팔레트가 필수.
3. **디라이팅**: 채널별 나눗셈은 색이 보색으로 뒤집힘(올리브화) → **휘도만** 플랫필드하고 전역 웜캐스트는 60%만 중화. 단, 블러 반경보다 큰 광 웅덩이는 못 지움 → §4.4로 해결.
4. **텍스처 전사**: 질감(고주파) = 휘도÷블러(비율, 0.70~1.38 클램프), 조명(저주파) = 블러에 흡수돼 버려짐. 중립 톤 × 비율로 재조합. **크로마는 전사 금지** — 잔광의 색조가 따라온다.
5. **발광체(불꽃·해·촛불)는 디라이팅 제외** — 알베도가 아니라 광원이므로 원본색 유지. 디라이팅하면 황록색으로 변색.
6. 디라이팅+양자화는 대비를 누른다 → 팔레트 `punch()`(명도 S커브 ×1.22, 채도 ×1.2, 발광체 제외)로 복원.
7. **배경 분리는 셀 좌표 규칙으로** (gen.py `static_sub`). 렌더된 rect를 bbox로 사후 분류하면 색 런 경계 때문에 오분류.
8. **mix-blend-mode를 그룹에 걸면 안 됨** — 자식의 multiply 그림자가 무력화. 블렌드는 자식별, 그룹은 opacity만.
9. CSS 규칙: 컴파운드는 input DOM 순서 의존(`#t-X:checked ~ #s-Y:checked ~ .scene` — 시간→계절→날씨 순 배치). 마스터 토글은 `!important`로 조건부 show를 이김. 패널 활성 표시는 `#input:checked ~ .panel label[for=...]`.
10. **mask 내부 요소도 CSS display 토글이 먹힌다** → 오클루더-소품 연동의 핵심.
11. 스프라이트 뒤 배경은 인페인팅(같은 행 최근접 비스프라이트 셀 복사) — 토글 off 시 구멍 방지.
12. 애니메이션: `steps()`로 픽셀 낙하감, 파티클은 타일+`<use y=-30>`+translateY(30px) 루프, 불꽃은 `transform-box:fill-box`+origin bottom, `prefers-reduced-motion`에서 일괄 정지.
13. **Claude 브라우저 패널 퀴크**: file:// 리로드 시 폼 상태를 DOM 위치 기반으로 복원해 토글이 뒤섞여 보임 → 검증은 javascript_tool로 상태 명시 후 스크린샷. 탭이 URL에 고정되기도 함(force navigate가 새 탭 생성).
14. 전환 직후 스크린샷은 transition(.6s) 중간이 찍힘 — 1초 대기 후 캡처. rect 수천 개 씬은 1.5초+ 대기하고, 의심되면 한 번 더 찍어 비교.
15. **색 검출 기반 스프라이트 마스크는 유사 색을 오염시킨다**: 나무 folia 조건(`abs(g-b)<18`)이 회보라 언덕·노을 하늘까지 흡수. 하부 창의 "나무 덩어리"는 실제론 언덕+줄기(x34-36)뿐이었음. → 창밖 오브젝트는 색 검출 대신 수작화/절차 생성.
16. **절차 바닥: 세로 조인트가 잦으면 벽돌담처럼 보인다** → 판자를 길게(26~38칸), 톤은 fb1 위주로 편중(fb0/fb2 각 20%), 나뭇결은 1px 대시 드문드문.
17. **클럼프 상단을 통짜 밝은 톤(t2)으로 칠하면 라임색 슬래브가 된다** → 릿지는 해시로 끊긴 세그먼트만.
18. 해 글로우를 어두운 클러스터(k4)로 하면 노을이 칙칙함 → 안쪽일수록 밝은 클러스터. 같은 셰이프가 밤엔 달무리로 재사용됨.
19. **스톱이 적을 때의 디더는 그라디언트가 아니라 격자 무늬로 보인다.** 베이어 4×4는 frac≈0.5에서 완벽한 체커보드가 되고, 인접 스톱 색차가 크면 그대로 눈에 띈다. → 해법은 디더가 아니라 **스톱 수를 늘리는 것**(7→10단). 촘촘해지면 디더 없이 solid 밴드로도 매끄럽다. 방사형(해 후광)처럼 밴드가 링으로 보이는 곳에만 해시 지터를 쓴다.
20. **산맥은 단색 실루엣 + 능선 1px 림**이 정석. 산맥 경계에 디더를 섞으면 얼룩(노이즈)으로 읽힌다. 능선에 1px 랜덤 지터를 더하는 것도 마찬가지 — 제어점 선형보간이 만드는 자연스러운 계단이 이미 도트 실루엣이다.
21. **나무 수관은 로브(타원)마다 개별 셰이딩**해야 잎 뭉치가 보인다. 수관 전체를 "열별 최상단으로부터의 깊이"로 셰이딩하면 아래쪽이 통째로 시커먼 덩어리가 된다. 음영값 = 세로위치×0.62 + 방사거리×0.38(둥근 puff), 로브 중심 y는 서로 어긋나게(같은 높이면 가로 줄무늬), 수관 사이 **하늘 틈**을 뚫어야 덩어리로 안 보인다.
22. **색대비는 명도보다 채도로.** 명도 S커브를 과하게(×1.5+) 올리면 어두운 방이 검게 뭉개져 오히려 대비가 죽는다. 명도 ×1.38 / 채도 ×1.72가 균형점.
23. 낮인데 실내가 밤처럼 어두우면 씬이 깨진다 → 낮 오버레이에 **screen 앰비언트**(rgba(140,170,208,.30))로 방을 들어올린다. multiply만으로는 시간대가 구분되지 않는다.
24. 바닥 판자의 세로 조인트가 잦으면 벽돌담이 된다 → 판자 길이 24~42칸, 조인트는 밴드마다 어긋나게, 결은 2~4px 가로 대시 + 드문 옹이, 판자 위/아래 1px 모따기로 두께감.

25. **측정된 "벽"은 평면이 아니라 소품 모양대로 오려진 껍데기였다.** g-wall 은 창·벽난로·책장 자리가 실제로 비어 있어, 패널에서 소품을 끄면 그 뒤로 창밖 하늘이 비쳤다. → `wall-plane` 을 g-wall **뒤에** 깔고 개구부는 창(art x27-66, y4-33) 하나만 남긴다. 레퍼런스 추출 그룹은 "그려진 것"이지 "구조"가 아니므로, 구조는 따로 세워야 한다.
26. **사각형으로 보이는 그림자는 알파 단계가 아니라 모양의 문제다.** 비네트가 네 변에 1px 띠 5줄, AO 가 큰 사각 5장이었다 — 단계를 늘려도 사각형은 사각형이다. → 중심에서의 **거리장을 3~4단으로 양자화**한다. 계단은 남기되(도트다움) 테두리는 사라진다.
27. **순수한 타원 거리장도 "도형을 덧댄" 티가 난다.** 등고선이 너무 반듯하기 때문. → 각도 3·5·2주기 사인을 겹쳐 반지름을 ±14% 흔들고(찌그러진 타원), 어둠의 중심을 화면 정중앙이 아니라 **광원 반대쪽으로** 옮긴다. 세로 띠형 AO 도 경계를 y 로 출렁이게 해야 직사각형을 면한다.
28. **정지 실루엣을 scaleY 로 눌렀다 폈다 하는 건 애니메이션이 아니다** — "숨쉬는 삼각형"으로 보인다. 불은 **프레임마다 실루엣 자체를 다시 만들어야** 한다(`flameFrames`, 6프레임). 다만 진폭이 크면 불이 춤을 춰 산만하다: 휨은 `pow(t,1.8)*w*0.26` 정도로 끝만 흔들고, 교체는 165ms(≈6fps), 광원 flicker 도 함께 줄인다.
29. **후광을 배경 생성기(synth)에 구워 넣으면 중심이 하나로 고정된다.** 해(58.5,17)와 달(56.5,16.5)이 위치가 달라 한쪽은 반드시 어긋난다 — 실제로 후광이 달에 맞춰져 있었다. → `halo-sun`/`halo-moon` 별도 그룹으로 분리해 시간대별로 켠다.
30. **가로로 균일한 구름 띠는 하늘 그라디언트와 겹쳐 줄무늬로 읽힌다.** → 띠가 아니라 중심이 흩어진 뭉게구름(타원 로브)을 겹치고, 윤곽을 저주파 사인으로 울퉁불퉁하게. 나무 수관과 같은 원리(레슨 21).
31. **방 안에서 보는 시점이면 창 바깥 처마 위의 눈은 보일 리가 없다.** 실측 프롭이 창 위(y2)에도 눈을 얹어 둬서 벽에 흰 막대가 떠 있는 것처럼 보였다. 안에서 보이는 수평 턱은 문설주(y21)와 창턱(y34) 둘뿐. z-순서도 **벽 위 · 창틀 뒤 · 돌 뒤**여야 "창턱에 쌓인 눈"으로 읽힌다.
32. 파티클을 창 폭에만 그리면 다른 씬(창이 더 큰 방·야외)에서 재사용할 수 없다. 아트 전폭으로 생성하고 **창이 잘라내게** 두는 편이 옳다 — 성능 부담은 없다(전폭 폭우도 rect 수천 개 수준). 세로 주기는 TILE_H(30)의 약수여야 이음매가 안 보인다.
33. 비와 폭우가 구분이 안 되면 **밀도·속도·창빛을 같이** 벌려야 한다. 밀도 4%/11%, 낙하 주기 1100ms/520ms, `--wl-a` .11/.04 로 5.8배 차이를 만들었다.

34. **측정 아트의 벽난로·책장은 완전한 직사각형이었다 — 두께 0 인 판자.** 게다가 밑변이 바닥선(y49) 바로 위였다. 즉 측정 위치는 **앞면이 아니라 벽면**이다. 그래서 옆면을 뒤로 붙이면 밑동이 벽 속으로 들어가 뜬다. 올바른 방향은 반대다: **앞면을 앞으로 끌어내 바닥에 세우고**(소실점 기준 확대 ×1.15) 벽면과의 사이를 옆면·윗면으로 잇는다.
35. **윗면이 보이는지는 수평선이 정한다.** 앞면 윗변이 벽면 윗변보다 **아래**면(=수평선 아래 물체) 윗면이 보인다 — 벽난로 맨틀. 수평선 위로 솟은 것(책장)은 앞면 윗변이 더 위라 윗면이 안 보인다. 눈높이보다 높은 책장 위가 안 보이는 것과 같다. 조건 없이 윗면을 그리면 책장에 없는 면이 생긴다.
36. **상자가 바닥에 서면 z-순서가 뒤집힌다.** 벽에 붙어 있을 땐 바닥을 나중에 그려도 됐지만, 밑동이 바닥선 아래로 내려오면 바닥이 밑동을 지운다 — 불만 바닥에 덩그러니 남았다. **바닥 → 벽난로·책장** 순서로.
37. 상자를 앞으로 끌어내면 **거기 얹힌 것이 전부 따라와야 한다** — 불꽃·촛대·책·맨틀 위 소품, 그리고 **광원 중심과 그림자 오클루더까지**. 하나라도 빠지면 그것만 벽에 붙어 남는다.

38. **어느 옆면이 보이는지는 소실점이 정하고, 어느 옆면이 밝은지는 광원이 정한다 — 둘은 다른 문제다.** 책장(중심 x86.5)은 소실점(x50.1)이 왼쪽이라 **왼쪽** 옆면이 보이는 게 맞다(방 한가운데서 볼 때 오른쪽 가구의 왼쪽 옆구리가 보이는 것과 같다). 그런데 그 면을 가장 어두운 슬롯으로 칠했더니 **가구가 반대로 돌아앉은 것처럼** 읽혔다. 두 옆면 다 창문(x27~66)을 마주 보므로 앞면보다 **밝아야** 한다. 방향 판별의 실질적 단서는 기하가 아니라 명암이다.

39. **측정 추출은 조명과 평면 색은 가져와도 "구조"는 못 가져온다.** 벽난로·책장을 픽셀 격자로 찍어 보니 둘 다 **모서리 1px 하이라이트가 하나도 없었다** — 그래서 이 크기에서는 선반 널·맨틀 턱·상인방이 전부 "그려 넣은 줄"로 읽혔다. 도트 가구는 면이 아니라 **모서리**로 읽힌다: 널 앞면 1px 밝게 + 밑면 1px 어둡게 = 두께.
40. **맨틀은 몸통보다 튀어나와야 벽난로다.** 측정본은 상판이 몸통과 정확히 같은 폭(x0~21)이라 턱이 없었고, 그래서 벽에 그린 그림처럼 보였다. 좌우 2px 돌출 + 윗면 밝게 + **턱 밑 그림자 1줄**(돌출을 증명하는 건 이 그림자다). 바닥 쪽에는 화덕(돌판)이 앞으로 튀어나와야 바닥에 놓인 물건이 된다.
41. **아궁이 안은 새까매야 불꽃이 산다.** 측정본은 잔광·장작이 중간톤으로 구워져 있어 아궁이가 구멍이 아니라 채워진 판으로 보였고, 그 위에 불을 얹으니 불이 벽에 붙은 스티커 같았다. 가장 어두운 슬롯으로 덮고 장작만 남긴다.

42. **벤치마킹은 텍스트 검색이 아니라 브라우저로 그림을 봐야 한다.** 웹 검색은 에셋 판매 페이지 제목만 돌려줘서 두 번 헛발질했다. 이미지 검색 결과를 브라우저로 열어 **스크린샷을 찍어 보는** 순간 필요한 규칙이 다 나왔다. 도트 레퍼런스는 글로 설명된 적이 거의 없다 — 그림을 봐야 한다.
43. **도트 벽난로의 필수 4요소**(레퍼런스 공통): ① 벽돌 켜 — 가로 줄눈 + 세로 이음매 엇갈림(막힌줄눈). 통짜 단색이면 판자로 보인다. ② **아치형** 아궁이 — 사각이면 문간이나 TV장이 된다. ③ **계단식 맨틀** — 위가 가장 넓고 아래로 좁아진다. 한 겹 턱보다 훨씬 잘 읽힌다. ④ 앞으로 튀어나온 화덕.
44. **도트 책장의 제1 단서는 "안쪽이 틀보다 확연히 어둡다"는 것.** 레퍼런스는 예외 없이 틀(밝은 나무) / 뒷판(어두움) 대비가 크다. 우리 측정본은 둘이 거의 같은 톤이라 통짜 판으로 보였다. 단, 칸 안에 이미 그려진 밝은 것(책·화분)은 남겨야 하므로 **어두운 배경 톤만 골라 덮는다**(SHELF_BG 집합).

45. **벽돌은 줄눈만 그으면 격자무늬가 된다.** 레퍼런스는 줄눈이 아니라 **장 한 장마다 명암**이 있다 — 윗면 밝고 아래·오른쪽이 줄눈. 블록 4×3, 켜마다 반 장 엇갈림, 장마다 톤을 조금씩 흔들어야(해시) 찍어낸 타일로 안 보인다.
46. **책장이 책장으로 읽히는 결정적 이유는 "따뜻한 나무 틀 vs 어두운 안쪽"의 재질 대비다.** 우리 측정본은 틀까지 방 색(보라)이라 벽에 묻어 있었다. 틀·널·옆면을 --wd0/1/2(나무)로 바꾸는 것만으로 형태가 살아났다. 방 팔레트에 맞추는 것보다 **재질을 구분하는 게** 우선이다.

47. **비가 "굵은 선"으로 보인 건 굵게 그려서가 아니라 이웃 열이 붙어서다.** 칸마다 독립으로 확률을 굴리면 x, x+1 이 동시에 뽑혀 2~3px 뭉치가 생긴다. 빗줄기는 언제나 1px 이어야 하므로 **열 단위로 그리고 바로 옆 열은 못 고르게 막는다**(rainCols). 비/폭우 차이는 열 밀도(20%/52%)·대시 길이(2/5)·주기(13/7)로만 낸다.
48. **구름 색을 BASE 에만 두면 노을·밤에 배경과 따로 논다.** 하늘(--kN)은 TIME 오버라이드가 있는데 구름(--cloud-N)은 없어서 하늘만 주황이 되고 구름은 회청색으로 남았다. 창밖 요소는 하늘과 **같은 축에서** 색이 바뀌어야 한다.
49. 창턱은 측정본이 x24~70(창은 x25~70)이라 왼쪽만 1칸 나온 짝짝이였다. 양옆 돌출을 같게 맞추면 그것만으로 정돈돼 보인다.

50. **"자국"은 색면이 아니라 그늘이다.** 돌이 눌러 앉았던 자리를 슬롯 색으로 칠했더니 러그 위에 파란 얼룩이 됐다. 눌린 자국은 알베도가 아니라 **AO** 다 — 타원 거리장 2단 multiply(RUG_MARK)로 옮기니 바로 자국으로 읽혔다. 그림자 계열은 그림자 패스에서 다뤄야 한다.
51. **깔개는 위에 놓인 물건보다 확실히 넓어야 깔개로 읽힌다.** 방석을 돌 폭(10)과 비슷하게 그렸더니 돌 밑에 낀 주황 선으로만 보였다. 18칸으로 넓혀 양옆으로 4칸씩 삐져나오게 하니 그제야 깔개가 됐다.
52. **측정 창틀에는 창짝(문설주·중간살)이 붙박이로 구워져 있다.** 창을 여닫으려면 뼈대와 창짝을 갈라야 한다(splitWinframe). 셀 단위로 문설주(x46~47)·중간살(y21의 유리 구간)만 골라 떼면 된다.
53. 소품 자리를 옮길 때는 **이미 그 자리를 쓰는 것**을 먼저 확인할 것. 찻잔을 "돌 옆"에 놓았더니 스탠드(x70~77)와 겹쳤다. 창턱 빈자리는 화분·돌·스탠드를 뺀 x33~48 뿐이었다.

54. **작은 물건은 "무엇인지"보다 "어느 것인지"가 안 읽힌다.** 펼친 책을 종이 위주로 그렸더니 6권이 전부 흰 덩어리로 똑같았다. 표지를 **테두리로 둘러** 좌우로 세워 보이게 하니 그제야 권마다 색이 구분됐다. 색으로 개체를 구별해야 하는 소품은 색면을 가장자리에 배치할 것.
55. 같은 물건이 두 곳에 동시에 있으면 안 된다 — 펼친 책이 바닥에 나와 있으면 **책장의 그 칸은 비어야** 한다. 상태 하나(readBook)로 두 그룹의 표시를 반대로 묶는다.

56. **"분위기를 모르겠다"의 정체는 접지 그림자였다.** 새 소품들은 시간·날씨 오버레이도, 광원도, 비네트도 전부 받고 있었다 — 빠진 건 **자기 발밑 그림자**뿐. 그게 없으면 아무리 잘 그려도 배경에 붙인 스티커로 보인다. 밑변 폭에서 시작해 한 줄마다 좁아지며 옅어지는 2줄(contactShadow)을 그림자 패스에서 일괄로 깐다. **앞으로 추가하는 소품은 GROUNDED 에 등록할 것.**
57. **무언가에 "파묻힌" 것처럼 보이려면 앞쪽 조각이 그 물건을 덮어야 한다.** 방석을 돌 밑에 깔기만 하면 그냥 돌 밑의 판이다. 방석을 두 조각으로 갈라 뒤쪽은 돌보다 먼저, **앞 테두리는 돌보다 나중에** 그려 밑동을 덮으니 그제야 파묻혔다.
58. **빈 그릇은 안을 어둡게 칠하면 검은 구멍이 된다.** 안쪽 벽(밝음)과 바닥(그늘)을 나눠 그려야 "비어 있다"로 읽힌다.
59. 부품을 나눈 소품(풍경 고리/대롱, 방석 뒤/앞)은 **부모 토글에 묶어야** 한다. 안 묶으면 패널에 토글이 없는 쪽이 영영 꺼진 채 남는다(풍경 대롱이 실제로 그랬다).

60. **비는 결국 실측 원본(1×3 짧은 낱방울을 성기게)이 정답이었다.** 네 판을 그렸고 원본이 제일 나았다: ①원본(낱방울) → ②per-cell 랜덤(이웃이 붙어 굵은 뭉치) → ③1px 열 기둥(정지한 선) → ④대각선(**최악**). 대각선이 실패한 이유가 중요하다 — 각도 자체는 레퍼런스가 맞지만 **낙하 애니메이션이 수직(dy)** 이라 기울어진 빗줄기가 옆으로 안 움직인다. 모양과 움직임이 어긋나면 정지한 빗금으로 보인다. 그리고 창이 38px 밖에 안 되는 이 스케일에서는 **긴 줄 자체가 과하다**.
61. **"고치는 것"과 "바꾸는 것"을 구분할 것.** 원본이 이미 괜찮았는데 세 번을 다시 그렸다. 지적이 반복되면 방향을 더 밀어붙일 게 아니라 **되돌려 볼 것**. 레퍼런스도 그대로 베끼면 안 된다 — 이 씬의 스케일과 애니메이션 방식에 맞는지 먼저 봐야 한다.
62. 상태가 둘인 소품(담요: 개어둠/감쌈)은 **같은 물건이므로 동시에 있으면 안 된다.** 하나의 상태 변수로 두 그룹을 배타적으로 묶는다 — 펼친 책↔책장 칸과 같은 패턴.

## 6. 생성 원칙 (아트를 코드로 그릴 때의 규칙)

1. **모든 에셋은 무광원 중립(albedo) + AO만** — 시간·날씨·광원 색을 절대 굽지 않는다. AO 허용 범위: 접지 그림자, 선반 안쪽, 틈새, 물체끼리 맞닿는 곳.
2. 시간·날씨 색감은 **오버레이 2장(multiply)** 으로.
3. 광원은 **셰이프 1장 + 상태별 색·세기 테이블**. 시간→기본, 날씨→오버라이드, 계절→컴파운드 예외.
4. 발광체만 **emission 분리**, 항상 최상단.
5. 그림자는 **오클루더**(빛 차단 실루엣, 단순 다각형)로 — 소품 on/off와 연동.
6. §3.4 z-순서 준수.
7. 도트: 96×72 그리드 기준, `shape-rendering: crispEdges`. 디테일(나뭇결·문양·노이즈)은 결정적 해시 디더(h2 함수)로 절차 생성 — 텍스처 전사는 러그처럼 문양이 복잡한 것만.
8. (삭제 — PixelLab 프롬프트 규칙이었다. §0.1로 폐기)
9. **창밖 오브젝트·바닥·돌은 색 검출 추출 금지** — 수작화(클럼프 좌표)나 절차 생성(ball/synth/판자)으로. 추출은 정적 구조와 발광체만.
