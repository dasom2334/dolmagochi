## 오답노트: 이미지 생성 요청에 파일·결과물을 건드리지 말 것 (2026-07-21)

사용자가 반복해서 요구한 것은 **이전 이미지를 구도·내용 레퍼런스로 넣고, 별도의 스타일
레퍼런스도 함께 넣어 새 이미지를 생성하는 것**이다. 이전 이미지를 빼라는 뜻이 아니다.
두 입력 이미지를 참고해 새로 생성하되, 기존 생성물을 직접 편집·변환하거나 로컬에서
후처리하라는 요청은 아니다.

### 실제로 잘못한 것

- 이전 이미지를 구도·내용 레퍼런스가 아니라 편집 대상으로 취급했고, 새로 나온 결과를
  다시 다음 호출의 입력으로 연결해 연쇄적으로 스타일 변환했다.
- "레퍼런스를 더 강하게"를 팔레트 압축·픽셀 확대·질감 단순화 지시로 과잉 해석했다.
- 사용자가 "두 번 더"라고 했을 때 같은 조건의 독립 생성 두 장이 아니라, 1차 결과를
  다시 변환하는 2차 패스로 실행했다.
- 생성 모델에 맡겨야 할 일을 대신 손보려 했고, 그 과정에서 액자·소품·구도·질감이
  사라지거나 달라졌다.
- 실제 출력 크기를 확인하지 않고 `128×72`라고 단정했다.

### 앞으로 반드시 지킬 것

1. 사용자가 **생성**을 요청하면 이미지 생성 도구만 호출한다.
2. 이전 이미지는 빼지 말고 매 호출에 **구도·내용 레퍼런스**로 넣는다. 단, 직접 수정할
   편집 대상으로 취급하지 않는다.
3. 별도로 지정된 레퍼런스 이미지는 매 호출에 **스타일 레퍼런스**로 함께 넣는다.
4. "두 번 생성"은 동일한 이전 이미지(구도·내용)와 동일한 스타일 레퍼런스, 동일한
   프롬프트를 사용한 **서로 독립적인 두 번의 생성**을 뜻한다. 첫 결과를 두 번째 입력으로
   사용하지 않는다.
5. 로컬 리사이즈·크롭·다운스케일·색상 수 축소·팔레트 압축·보간·필터·인페인팅·파일
   덮어쓰기를 하지 않는다. 사용자가 그 작업을 따로 명시했을 때만 한다.
6. "레퍼런스를 강하게"는 프롬프트에서 스타일 우선순위를 높이라는 뜻이지, 기존 그림을
   변환하거나 소품을 삭제하라는 뜻이 아니다.
7. 창·책상·의자 등받이·침대·러그·액자·선풍기·음료처럼 사용자가 지정한 소품과 구도는
   프롬프트에 보존 대상으로 적는다.
8. 지나친 금지 조건과 기술 용어를 쌓아 모델을 경직시키지 않는다. 레퍼런스 우선, 장면
   내용, 반드시 보존할 요소만 간결하게 적는다.
9. 생성 결과가 실제로 `128×72`인지 확인하지 않았다면 정확한 크기라고 말하지 않는다.
10. 결과가 잘못되면 오답을 숨기지 말고 무엇이 어긋났는지 설명한다. 단, 다음 시도에서도
    결과물을 직접 고치지 않고 레퍼런스와 수정된 프롬프트로 새로 생성한다.

### 금지된 연쇄 작업

`생성 결과 A → 스타일 변환 B → 팔레트/픽셀 압축 C → 재변환 D`

### 올바른 반복 생성

`이전 이미지(구도·내용 레퍼런스) + 스타일 레퍼런스 + 수정된 프롬프트 → 새 생성 A`

`동일한 이전 이미지 + 동일한 스타일 레퍼런스 + 동일한 프롬프트 → 새 생성 B`

두 결과는 서로의 입력이 아니다.

## 거실과 결정적으로 다른 점 — 측정이 필요 없다

레퍼런스가 **128×72 네이티브 · 16색**이다. 앱 캔버스(`GX=128, GY=72`)와 1:1 이라
거실에서 했던 격자 검출(셀 15.08px) · 리전 k-means · 인페인팅이 **전부 불필요**하다.
남는 일은 "측정"이 아니라 **레이어 분리**(무엇이 벽/바닥/창/가구/소품인지 이름 붙이기)다.

`tools/gen.py` 는 거실 좌표가 하드코딩(`WIN`·`ORB`·`BOOKS`)돼 있는데,
침실에는 그 파이프라인 자체를 안 돌려도 된다.

## 미해결: 밤이 그림에 구워져 있다

`design/livingroom/README.md` §6 원칙 1 — "모든 에셋은 무광원 중립(albedo)+AO만,
시간·날씨·광원 색을 절대 굽지 않는다". 그런데 이 레퍼런스는 밤이 알베도에 섞여 있다.

창을 뺀 방 안만 보면 평균 명도 **13.3/255**, 90퍼센타일 31. 상위 3색
(`#04020b` `#080613` `#10060d` — 명도 3.6/8.1/9.8)이 화면의 **68%**이고,
밝은 색 4개는 합쳐 2% 미만인데 전부 발광체(달·모니터·램프·촛불)다.

거의 검정인 픽셀은 낮 오버레이로 들어올려도 색이 살아나지 않고 탁한 회색이 된다.
거실은 명도 중앙값 50이라 `delight.py` 가 먹혔지만 이건 8이다.

→ **낮(또는 중립 조명) 버전이 오면 그것을 알베도 기준으로 삼고, 이 밤 그림은
밤 오버레이의 목표값으로 쓴다.** 두 장 사이를 보간하는 편이 역산보다 정확하다.

## 돌의 자리 (2026-07-21 확정)

| 상황 | 위치 |
|---|---|
| 개인작업 집중 | 책상 **의자** |
| 누워있기 — 침대 구매함 | **침대** |
| 누워있기 — 침대 없음 | **러그** |

거실이 `orb: 'sill' | 'rug'` 두 자리인 것처럼 침실은 세 자리다.
침대는 `pillow` → `bed` 순으로 해금되는 상점 물건이라, 안 샀으면 침대가
씬에 없어야 한다 — "침대가 없으면 러그"는 게이팅과 같은 조건을 본다.

## 이 방에 들어가야 하는 것 (게임 데이터)

캡션 "침실. 책상과 침대."

| 계열 | 소품 | 비고 |
|---|---|---|
| 누워있기 | 베개 → 침대 | 베개를 사야 침대를 살 수 있다 |
| 개인작업 | 책상 → 문구 → 노트북 | 순서대로 해금 |
| 조명 | 스탠드(`lamp`) | 거실 스탠드(`floorlamp`)와 **다른 물건** |
| 소모품 | 야식(`nightdrink`), API 토큰(`apitoken`) | 재고 표시 자리 필요 |

상점 물건은 사기 전엔 안 보여야 하므로 배경에 굽지 말고 따로 뗄 수 있어야 한다
(거실에서 벽난로·담요가 이 문제로 걸렸다).

## 구조 (확정)

- **바닥은 거실 것을 재사용** (절차 생성 판자).
- **창은 재사용 불가** — 침실 창은 **왼쪽**이고 바깥 구도도 다르다. 거실은 창이
  가운데(art x27~66)라 `lights.js` 의 창광 사다리꼴(skew 방향)과 색감 오버레이
  영역 분할이 전부 그 전제로 잘려 있다. 둘 다 새로 잡아야 한다.
- 하늘·산·해달별·구름·날씨 파티클·색감 오버레이·비네트·접지 그림자는 재사용.
